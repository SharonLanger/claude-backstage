## Reader's orientation

The study isolates a question a developer can encounter before editing a prompt or accumulating conversation history. If the same zero-shot Python problem is submitted repeatedly to the same model configuration, how much does the generated program change? Across three benchmarks, the authors found variation in program text, structure and test behavior. Some tasks went from a candidate that passed every test to one that passed none. Across the two observed GPT snapshots, the evidence supports vulnerability to run-to-run variation at temperature zero as well as at the study's default of one. These estimates describe the benchmark settings. They leave sequential feedback, retry convergence, agent editing and parallel developer work unmeasured. [ACM version of record, abstract and §§2–4](https://kclpure.kcl.ac.uk/ws/files/365277933/An_Empirical_Study_of_the_Non-Determinism_of_ChatGPT_in_Code_Generation_Version_of_Record.pdf)

## Detailed analytical reading

### Five candidate generations held the task and prompt constant

The baseline generates five Python 3 candidates per problem by making five API calls with the same user prompt. Each call asks for Python formatted as Markdown and includes the original problem text. It gives the model no worked example or feedback from previous candidates. Section 3.3 identifies the API snapshots as `gpt-3.5-turbo-0125` and `gpt-4-0613`. It reports `top_p=1` and one completion choice per call in the main comparisons. Section 4.3 is the exception that also evaluates five choices returned by one request. The paper's reporting of these API conditions does not establish seed-controlled replay or isolate backend effects. [ACM §§2–3.3, pp. 42:3–42:6](https://kclpure.kcl.ac.uk/ws/files/365277933/An_Empirical_Study_of_the_Non-Determinism_of_ChatGPT_in_Code_Generation_Version_of_Record.pdf#page=5)

The 829 tasks consist of the 165-problem CodeContests test set, 500 of 5,000 randomly sampled APPS test problems, and all 164 HumanEval tasks. Table 1 reports mean test cases per task of 203.84, 80.43 and 9.24, respectively. CodeContests and APPS include programming challenges, while HumanEval supplies handwritten function-oriented tasks. The authors extracted code unchanged and ran benchmark tests sequentially, mainly on Linux cloud VMs. They used a three-second timeout, also applying it to APPS, for which they report no default. They captured each candidate's pass rate and individual test outputs. A problem and its shared test suite define the comparison unit, with five observations within each problem. [ACM §§2 and 3.2, Fig. 1 and Table 1](https://kclpure.kcl.ac.uk/ws/files/365277933/An_Empirical_Study_of_the_Non-Determinism_of_ChatGPT_in_Code_Generation_Version_of_Record.pdf#page=6)

### Output agreement and correctness tell different stories

For each task, the authors compare the largest and smallest pass rates across candidates and compute their variance and mean. The all-five output equivalence rate (OER) counts the share of test inputs on which all five candidates return the same recorded result. OER can count matching errors or timeouts as agreement. The paper reports a second measure excluding exception and error matches and a separate mean computed from pairwise comparisons. For a nonempty suite, OER=0 says each tested input has at least one disagreement across the five. For example, if four candidates return the same result on every input and a fifth returns a different result on every input, the all-five OER is zero even though four candidates agree completely. Identical output can also be identically wrong. For the textual comparison, the paper reports token-level LCS and Levenshtein edit distance. For structure, it compares normalized Python abstract syntax trees using the two `pycode_similar` settings. Each describes a particular kind of similarity. [ACM §3.4, pp. 42:7–42:8](https://kclpure.kcl.ac.uk/ws/files/365277933/An_Empirical_Study_of_the_Non-Determinism_of_ChatGPT_in_Code_Generation_Version_of_Record.pdf#page=8) · [Companion OER implementation](https://github.com/ShuyinOuyang/LLM-is-a-box-of-chocolate/blob/main/syntactic_similarity_OER.py#L39-L101)

### Temperature, model snapshots and how candidates were requested

At temperature zero, the share of tasks with OER=0 was 43.64% for CodeContests, 27.40% for APPS and 18.29% for HumanEval. At 0.5 the shares were 62.42%, 42.20% and 26.83%, using main Table 5 for CodeContests and appendix Tables 2–3 for APPS and HumanEval. Across 0, 0.5 and 1 for CodeContests, mean test pass rates were 0.15, 0.16 and 0.16, while mean within-task maximum pass-rate differences were 0.11, 0.15 and 0.24. Lower dispersion and similar average pass rates can coexist. The structural measures did not all rank 0 and 0.5 in the same order. The configuration paragraph lists temperatures 0, 1 and 1.5, while §4.2 and Table 5 report 0, 0.5 and 1. Use the reported values when citing results. The authors discuss potential causes for remaining variation at zero, including floating-point and backend execution effects, and provide no causal test to distinguish them. [ACM §§3.3 and 4.2, Table 5, pp. 42:6 and 42:12–42:13](https://kclpure.kcl.ac.uk/ws/files/365277933/An_Empirical_Study_of_the_Non-Determinism_of_ChatGPT_in_Code_Generation_Version_of_Record.pdf#page=14) · [Appendix Tables 1–3, pp. 6–7](https://github.com/ShuyinOuyang/LLM-is-a-box-of-chocolate/blob/main/Appendix.pdf)

For the model comparison in CodeContests, Table 7 reports GPT-4 versus GPT-3.5 OER=0 shares of 46.06% versus 75.76% at temperature 1 and 41.21% versus 43.64% at temperature 0. Mean pass rates at temperature 1 were 0.14 and 0.16 respectively. At zero, GPT-4 still showed OER=0 on 25.20% of APPS and 13.41% of HumanEval tasks in appendix Tables 8–9. The two models' temperature-zero results look similar on some metrics while retaining structural differences. Follow Table 7 for metric direction because the preceding prose reverses the direction of several similarity measures. This comparison is specific to the named snapshots and evaluated workload. [ACM §4.5, Table 7, pp. 42:17–42:18](https://kclpure.kcl.ac.uk/ws/files/365277933/An_Empirical_Study_of_the_Non-Determinism_of_ChatGPT_in_Code_Generation_Version_of_Record.pdf#page=20) · [Appendix Tables 8–9, p. 16](https://github.com/ShuyinOuyang/LLM-is-a-box-of-chocolate/blob/main/Appendix.pdf)

For CodeContests at temperature 1, §4.3's two ways of getting five candidates produced the same mean all-five OER of 0.09 and pairwise mean OER of 0.27, as rounded in Table 6. The two structural scores were much higher when candidates came from one API request. At temperature zero, one request with five choices yielded greater measured agreement than five separate calls. For example, mean pairwise OER excluding exceptions was 0.81 from one request and 0.46 across separate requests. The corresponding zero-temperature comparisons in the appendix were 0.90 versus 0.65 on APPS and 0.92 versus 0.82 on HumanEval. Table 6's single-request, zero-temperature row also pairs an observed maximum pass-rate spread of 0.00 with a nonzero worst-case share, a reporting ambiguity that precludes using that cell to infer a zero failure rate. RQ3 tests grouping choices into requests, with no comparison of developer workflow, concurrent against sequential scheduling, or selection quality. [ACM §4.3, Table 6, pp. 42:14–42:15](https://kclpure.kcl.ac.uk/ws/files/365277933/An_Empirical_Study_of_the_Non-Determinism_of_ChatGPT_in_Code_Generation_Version_of_Record.pdf#page=16) · [Appendix Tables 4–6, pp. 8–9](https://github.com/ShuyinOuyang/LLM-is-a-box-of-chocolate/blob/main/Appendix.pdf)

### Task differences, wording and candidate selection

In CodeContests at temperature 1, Figure 6 reports associations between description length and mean LCS (−0.29), mean edit distance (+0.38) and mean test pass rate (−0.22). The study compares different problems here, so it leaves open whether shortening any one prompt would help. The paper's two worked examples illustrate why structure and correctness merit separate inspection. The five solutions to the telephone-pole challenge all passed the suite despite mean structural similarity scores of 0.21 and 0.38. The array-query challenge had OER=0 and test-pass-rate variance of 0.13. [ACM §4.4 and Fig. 6, pp. 42:15–42:17](https://kclpure.kcl.ac.uk/ws/files/365277933/An_Empirical_Study_of_the_Non-Determinism_of_ChatGPT_in_Code_Generation_Version_of_Record.pdf#page=17)

For one direct wording comparison on CodeContests at temperature zero, the concise-code request, baseline request and reasoning-steps-first request gave OER=0 shares of 41.82%, 43.64% and 46.06%, respectively. Mean pass rates were 0.16, 0.15 and 0.19, and mean LCS scores were 0.70, 0.61 and 0.38. For both mean structural measures, the reasoning-steps-first condition scored higher than baseline and lower than the concise-code request. The differences at temperature one were less clear across the measures. A narrower wording change can affect stability and observed correctness differently, even on the same benchmark. [ACM §4.6, Table 8, pp. 42:18–42:19](https://kclpure.kcl.ac.uk/ws/files/365277933/An_Empirical_Study_of_the_Non-Determinism_of_ChatGPT_in_Code_Generation_Version_of_Record.pdf#page=21)

The authors retrospectively identify better candidates among the five using the benchmark test results. That demonstrates room for selection with a reliable evaluator. It leaves reviewer time, selection accuracy on unseen requirements and production outcomes unmeasured. Section 7.2 also reports repeated error types among candidates when all failed the tests, including index and name errors at temperature zero. Separate calls can express common mistakes. Voting and model-driven repair loops appear in §7.3 as future work. [ACM §§7.2–7.3, pp. 42:23–42:24](https://kclpure.kcl.ac.uk/ws/files/365277933/An_Empirical_Study_of_the_Non-Determinism_of_ChatGPT_in_Code_Generation_Version_of_Record.pdf#page=25)

The companion appendix makes this distinction concrete for HumanEval/151 at temperature zero. Three illustrated candidates passed three, four and five of seven tests. The five-of-seven candidate computed the intended sum for qualifying integers and still omitted the requirement to skip non-integers. A lower-scoring candidate included an explicit integer check and returned twice the requested sum. Candidate comparison exposed complementary mistakes, while the best observed score still came with a known requirement failure. [Companion appendix, pp. 5–6, Listings 1–5](https://github.com/ShuyinOuyang/LLM-is-a-box-of-chocolate/blob/main/Appendix.pdf)

## Extractable practitioner insights

- **OB-06, same wording, different behavior.** The direct evidence covers differences both in what was generated and how it behaved under fixed tests. Treat the generated artifact and its test results as the record when repeating a request can yield a different implementation. Recording the actual prompt, model settings and test result alongside the artifact is a catalog adaptation of the authors' reproducibility discussion. The study supplies no universal retry limit and did not follow an assistant incorporating feedback over time. SRC-0019:C01–C04, C06, C09 and C11.
- **BP-08, compare candidates against a common acceptance check.** The study supports the premise that repeated calls can yield different options and that a shared test suite can distinguish some of them. A repository workflow in which a person compares a few isolated candidate patches from the same starting revision against fixed tests and inspects the surviving diffs is an adaptation. It needs additional evidence to claim a benefit from parallel execution, an optimal candidate count, or a controlled improvement in delivery time or quality. SRC-0019:C03, C05, C08 and C12.
- **BP-08, repeated failures are diagnostic evidence.** A second candidate with a similar error can point toward an omitted edge case or ambiguity worth investigating. Candidates from the same model and task share important inputs, and practical execution might also reuse the same tests or tools. Use production requirements and independent verification as the acceptance basis. Treat agreement among attempts as corroboration only to the extent justified by the checks performed, and avoid calculating success odds from an assumed independent per-attempt probability. The diagnosis and acceptance workflow are catalog adaptations. SRC-0019:C02, C05 and C08–C09.

## Related work, conflicts, and limitations

- The published paper and its earlier manuscript and repository are one study. CodeContests, APPS and HumanEval diversify the tasks without constituting three independent studies. The authors report a HumanEval sensitivity check with EvalPlus that produced similar evaluation results. The paper describes this check in §5. [ACM §5, p. 42:20](https://kclpure.kcl.ac.uk/ws/files/365277933/An_Empirical_Study_of_the_Non-Determinism_of_ChatGPT_in_Code_Generation_Version_of_Record.pdf#page=22)
- A fixed test suite probes a finite set of observations. Test cases, timeouts and evaluation conventions differ among benchmarks. The test data support the measured comparisons and leave maintainability, security, regression risk, and behavioral equivalence beyond the observed inputs unresolved. [ACM §§2, 3.2, 3.4.1 and 5](https://kclpure.kcl.ac.uk/ws/files/365277933/An_Empirical_Study_of_the_Non-Determinism_of_ChatGPT_in_Code_Generation_Version_of_Record.pdf)
- The comparison is among single-turn Python-generation tasks on historical API snapshots. Retrying a repository task in an agent may also change context, repository state, model routing and tool evidence. The source gives no rates for those conditions or for current deployed assistants. [ACM §§2, 3.3 and 5](https://kclpure.kcl.ac.uk/ws/files/365277933/An_Empirical_Study_of_the_Non-Determinism_of_ChatGPT_in_Code_Generation_Version_of_Record.pdf)
- Printed prose and result tables disagree about a few figures and metric directions. The ledger follows Tables 2, 5 and 7 and the accompanying exact benchmark figures where checked. Absolute-looking numbers in the single-request temperature-zero row of Table 6 warrant care. The central finding of observed variability across separate requests survives those discrepancies. [ACM §§4.1–4.3 and 4.5, Tables 2, 5–7](https://kclpure.kcl.ac.uk/ws/files/365277933/An_Empirical_Study_of_the_Non-Determinism_of_ChatGPT_in_Code_Generation_Version_of_Record.pdf)
