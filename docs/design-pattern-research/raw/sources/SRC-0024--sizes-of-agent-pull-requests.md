## Reader's orientation

Ogenrwot and Businge compared merged GitHub pull requests (PRs) labeled Agentic and Human by the AIDev dataset. The pooled rank comparisons favor higher commit counts and more cumulative line changes for the selected Human group. The addition and total line-change effects are small by the paper’s conventions. This challenges the AP-07 claim that agent-associated work typically reaches merge with more line churn. The notebook’s file counts use different definitions by group, and its plotting code leaves named-agent comparisons uncertain. The design also leaves open how often agent use produces oversized drafts, how often people narrow drafts before merge, and whether large patches overwhelm reviewers. [§3, Figs. 2–3 and Table 1, PDF p. 3](https://arxiv.org/pdf/2601.17581v3#page=3) · [RQ1 notebook, cells 4, 8 and 13–16](https://github.com/unlv-evol/AgenticPR-MSR-2026/blob/v1.0.0/notebooks/RQ1_patch_characteristics.ipynb) · [§6, PDF p. 4](https://arxiv.org/pdf/2601.17581v3#page=4)

## Detailed analytical reading

### Cohorts and the meaning of the labels

The challenge snapshot was retrieved on November 1, 2025. The authors describe a release with 932,791 Agentic PRs, 6,618 Human PRs, 116,211 repositories overall and a curated enriched subset. The challenge lists 33,596 Agentic PRs in the curated subset, which is also the number of Agentic rows loaded by the tagged RQ1 notebook. That notebook loads 6,618 Human rows. It filters to 24,014 Agentic and 5,081 Human merged PR rows, the numbers reported in the paper, then joins commit details and calculates RQ1 metrics for 24,014 Agentic and 5,080 Human PRs. These populations have different coverage and the overall release counts are unsuitable denominators for calculating merge rates from the study counts. [§2, steps 1–3 and Fig. 1, PDF pp. 1–2](https://arxiv.org/pdf/2601.17581v3#page=1) · [Mining Challenge dataset description](https://conf.researchr.org/track/msr-2026/msr-2026-mining-challenge) · [RQ1 notebook, cells 2–4 and 8](https://github.com/unlv-evol/AgenticPR-MSR-2026/blob/v1.0.0/notebooks/RQ1_patch_characteristics.ipynb)

Agent commit data came from AIDev. The authors fetched Human commit and per-file information from GitHub’s REST API. The paper describes requiring unified diffs for every modified file of a valid commit and excluding Human cases with unavailable repositories, commits or complete patches. The tagged RQ1 code joins commit details and has no explicit per-file patch-validation step. The tagged RQ2 code assembles available file patches at PR level and removes PRs with empty combined diffs. Neither path documents a completeness check over all files of every commit. GitHub can omit or truncate very large patches, and data availability can differ by group. The magnitude and direction of any resulting bias remain unknown. [§2, steps 2–3, PDF p. 2](https://arxiv.org/pdf/2601.17581v3#page=2) · [§6, PDF p. 4](https://arxiv.org/pdf/2601.17581v3#page=4) · [RQ1 notebook, cells 2–8](https://github.com/unlv-evol/AgenticPR-MSR-2026/blob/v1.0.0/notebooks/RQ1_patch_characteristics.ipynb) · [Agentic RQ2 notebook, cells 1–5](https://github.com/unlv-evol/AgenticPR-MSR-2026/blob/v1.0.0/notebooks/RQ2_AgenticPRs_code_description_consistency.ipynb) · [Human RQ2 notebook, cells 4–10](https://github.com/unlv-evol/AgenticPR-MSR-2026/blob/v1.0.0/notebooks/RQ2_HumanPRs_code_description_consistency.ipynb)

The analysis inherits AIDev labels and reports no separate authorship validation. The AIDev builders’ original release methods document branch prefixes, bot accounts and explicit Claude co-author text as examples of observable signals. They describe selecting comparison PRs from the same popular repositories after excluding PRs created by the recognized autonomous agents. Those methods describe an earlier release with a different Human cohort count (6,628), so they provide background on how the labels were constructed and leave the exact challenge snapshot’s labeling and pairing details unverified here. Visible agent attribution can include collaborative work, and Human-labeled PRs can contain unmarked assistance from the same or other tools. The groups therefore represent dataset labels for PRs with different observed attribution, and the study never assigns the same task to a human and an agent under comparable conditions. Differences may reflect what work is delegated, where it is undertaken or how it is submitted. [Study §2, PDF pp. 1–2](https://arxiv.org/pdf/2601.17581v3#page=1) · [AIDev builders’ original paper, §§3.1–3.2 and Table 2](https://arxiv.org/html/2507.15003v1#S3)

### Structural measures and what the distributions show

RQ1 counts unique commit SHAs per PR in both groups. It sums per-file addition and deletion counts from Agentic commit details and commit totals from Human details. Code added in one commit and removed in a later commit can contribute to both totals while vanishing from the final PR diff. The paper describes counting unique file paths across commits and treating reported renames as single-file modifications. In the tagged notebook only the Agentic calculation counts distinct filenames across a PR. The Human calculation sums commit-level file counts. A Human PR that modifies the same five paths in two commits contributes ten file touches under the notebook’s formula. The reported rank difference for files therefore compares different quantities across the two groups, with repeat edits potentially inflating the Human count relative to a unique-path measure. [§2, steps 2 and 4, PDF p. 2](https://arxiv.org/pdf/2601.17581v3#page=2) · [RQ1 notebook, cells 4, 7–8 and 13](https://github.com/unlv-evol/AgenticPR-MSR-2026/blob/v1.0.0/notebooks/RQ1_patch_characteristics.ipynb)

| PR metric | Cliff’s δ as printed | Effect size as classified by the paper |
|---|---:|---|
| Commits | 0.5429 | Large |
| Files touched | 0.4487 | Medium |
| Deletions | 0.4462 | Medium |
| Line changes, additions plus deletions | 0.3158 | Small |
| Additions | 0.2836 | Small |

The paper reports two-sided Mann–Whitney results at p ≤ 0.001. The notebook’s saved pooled results match the five printed Cliff’s δ values. The code places the Human group first, so a positive δ means a randomly paired Human observation exceeds an Agentic observation more often than the reverse, with ties contributing zero. This gives the direction of the rank comparison for commit counts and cumulative line metrics in the selected sample. The files-touched result retains the asymmetric calculation described above. A rank effect leaves the mean, the prevalence of unusually wide changes and any reviewer difficulty threshold undetermined. [§3, RQ1 and Table 1, PDF p. 3](https://arxiv.org/pdf/2601.17581v3#page=3) · [RQ1 notebook, cell 13](https://github.com/unlv-evol/AgenticPR-MSR-2026/blob/v1.0.0/notebooks/RQ1_patch_characteristics.ipynb)

The paper calls 440,295 Agentic and 23,242 Human observations valid-patch commits. The tagged RQ2 notebooks print those exact numbers as counts of joined commit-file detail rows before excluding PRs with empty combined diffs. A commit can span multiple file rows. Dividing those detail counts by the paper’s PR counts cannot recover the mean number of distinct commits per PR. The RQ1 effect size comes from the separate per-PR unique-SHA calculation. [§2, steps 3–4, PDF p. 2](https://arxiv.org/pdf/2601.17581v3#page=2) · [RQ1 notebook, cells 4, 8 and 13](https://github.com/unlv-evol/AgenticPR-MSR-2026/blob/v1.0.0/notebooks/RQ1_patch_characteristics.ipynb) · [Agentic RQ2 notebook, cells 1–4](https://github.com/unlv-evol/AgenticPR-MSR-2026/blob/v1.0.0/notebooks/RQ2_AgenticPRs_code_description_consistency.ipynb) · [Human RQ2 notebook, cells 4–9](https://github.com/unlv-evol/AgenticPR-MSR-2026/blob/v1.0.0/notebooks/RQ2_HumanPRs_code_description_consistency.ipynb)

The authors describe wider spreads for Claude Code and OpenAI Codex and more compact distributions for Devin, Cursor and GitHub Copilot. The tagged cells for plotting lines, commits and files use the order of first appearance for their tick labels and the default sorted `groupby` order for their series. Human rows come first in the appended data. The group order of the plotted arrays and the tick labels can therefore differ, and the tagged plots cannot verify the named-tool interpretation in the PDF. The pooled tests select their groups explicitly. The task and repository mix also remain uncontrolled for per-tool comparisons. [§3, RQ1, Figs. 2–3, PDF p. 3](https://arxiv.org/pdf/2601.17581v3#page=3) · [RQ1 notebook, cells 10 and 13–16](https://github.com/unlv-evol/AgenticPR-MSR-2026/blob/v1.0.0/notebooks/RQ1_patch_characteristics.ipynb)

### Description similarity and review outcomes

RQ2 compares concatenated PR title and body with code diff text. The paper describes requiring complete description text and stripping diff metadata. The tagged notebooks concatenate available patch strings, fill missing title or body values with empty strings and apply the scorers to the combined text. The released code does not show the paper’s metadata-stripping step. The saved notebooks drop 38 Agentic and 35 Human PRs with empty combined diffs, leaving 23,976 and 5,045 respectively. None of those remaining PRs has an empty combined title and body. [§2, step 4, PDF p. 2](https://arxiv.org/pdf/2601.17581v3#page=2) · [Agentic RQ2 notebook, cells 1–8](https://github.com/unlv-evol/AgenticPR-MSR-2026/blob/v1.0.0/notebooks/RQ2_AgenticPRs_code_description_consistency.ipynb) · [Human RQ2 notebook, cells 4–15](https://github.com/unlv-evol/AgenticPR-MSR-2026/blob/v1.0.0/notebooks/RQ2_HumanPRs_code_description_consistency.ipynb)

Table 2 reports Agentic and Human medians of 0.0937 and 0.0680 for TF–IDF, 1.0169 and 0 for the measure labeled BM25, 0.9375 and 0.9347 for CodeBERT, and 0.8302 and 0.8067 for GraphCodeBERT. The tagged Human notebook’s saved GraphCodeBERT median is 0.806617, which rounds to 0.8066. The notebooks compute the BM25-derived quantity as `score / (score + 10)`. This transform can yield extreme values near a raw score of −10, so its result is a relative comparison under the study’s scoring choices. Each semantic tokenizer truncates the text to at most 512 tokens in the tagged code, which limits what a score can represent for a large diff. Review time, reviewer comprehension and code correctness were outside the outcomes measured. [§2, step 4, PDF p. 2](https://arxiv.org/pdf/2601.17581v3#page=2) · [§3, RQ2, Table 2 and §6, PDF p. 4](https://arxiv.org/pdf/2601.17581v3#page=4) · [Agentic RQ2 notebook, cells 7–8, 10 and 13](https://github.com/unlv-evol/AgenticPR-MSR-2026/blob/v1.0.0/notebooks/RQ2_AgenticPRs_code_description_consistency.ipynb) · [Human RQ2 notebook, cells 13–15, 18 and 23–24](https://github.com/unlv-evol/AgenticPR-MSR-2026/blob/v1.0.0/notebooks/RQ2_HumanPRs_code_description_consistency.ipynb)

## Extractable practitioner insights

**AP-07 Big chunk working.** The anti-pattern describes an agent producing one change that bundles several intended outcomes or spreads unexpected edits across the repository. C05 challenges the claim that detected agent contributions generally reach merge with more cumulative line churn in this sample. The file measurement (C04) cannot establish relative breadth, and the data contain no measure of the number of independent behaviors bundled together. Oversized or abandoned drafts remain outside the selected sample (C01–C02), and the study gives no rate for unusually broad PRs. The practical question is whether the specific diff can be reviewed as one change under the team’s own conditions. [§§2–3, PDF pp. 2–3](https://arxiv.org/pdf/2601.17581v3#page=2) · [RQ1 notebook, cells 4, 8 and 13](https://github.com/unlv-evol/AgenticPR-MSR-2026/blob/v1.0.0/notebooks/RQ1_patch_characteristics.ipynb)

**BP-05 Slice for review.** The authors’ proposed triage uses commits and files touched alongside line counts (C09). A practitioner adaptation is to inspect the final diff against the requested outcome, then examine whether the affected behaviors depend on each other. A fix that changes a small public interface across many callers could be one coherent review. A short diff that combines a cleanup with an unrelated behavior change could merit a split. The paper supplies no validated triage thresholds, and the notebook’s file measurement (C04) limits comparisons of breadth across groups. The study did not assess slicing. [§4, PDF pp. 3–4](https://arxiv.org/pdf/2601.17581v3#page=3)

## Related work, conflicts, and limitations

- Pocock’s ticket decomposition guidance describes delivering an observable behavior per slice. This paper supplies counterevidence to greater cumulative line churn among agent-labeled PRs in its selected sample. The two publications leave the effect of slicing on review effort unmeasured. [SRC-0006](SRC-0006--vertical-slices-for-agent-tickets.md) · [PAT-0003](../patterns/PAT-0003--slice-a-change-for-review.md)
- AIDev is upstream data. Other Mining Challenge papers using the same release may overlap with the PRs in this study. The proceedings listing, arXiv version and replication package also describe the same study. Deduplicate evidence about the observed PRs by dataset, observation window and selection. [Study §2, PDF p. 1](https://arxiv.org/pdf/2601.17581v3#page=1) · [Mining Challenge dataset description](https://conf.researchr.org/track/msr-2026/msr-2026-mining-challenge)
- Selection on merge omits rejected, pending and abandoned submissions. Size may affect what gets merged, and the selected sample also omits work that was never opened as a PR. Connecting task size to agent use or reviewer effort would require observations of original task and draft scope, relevant human changes before submission or merge, and reviewer outcomes. The paper cautions that other review cultures, private repositories and newer agent versions can have different distributions. [§2, step 3, PDF p. 2](https://arxiv.org/pdf/2601.17581v3#page=2) · [§§6–7, PDF p. 4](https://arxiv.org/pdf/2601.17581v3#page=4)
