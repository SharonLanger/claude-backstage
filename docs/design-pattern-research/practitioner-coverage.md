Suffixes mark separate problems within one sentence or example where the available guidance differs. The focus column gives an alias or explicitly narrows a supplied example. The conceptual hints come from the design and do not imply catalog entries.

**Covered** means an existing entry gives a practical response under the stated controls. **Partially covered** means the entry helps with only part of the problem or offers only a system-level response to a practitioner question. **Missing** means the candidates do not give an applicable action for that focus. The linked catalog files are the candidates read for each judgment. Bridge references name installed rows or explicitly identify future route candidates. Proposed family homes are for later intake.

## Static route walkthroughs

These walkthroughs follow the local files and inspect the actual entries under representative constraints. They are separate from the installation check and from a conversation executed in Claude.

### Deleted regression test and a new bug (P-S01a, P-S01b)

- **Constraints and distinction.** A CLI coding agent can edit source and tests. The user can restrict write access and run the trusted baseline independently. Was the test change an approved requirement, and is there an independent reproducer for the new bug?
- **Route checked.** Bridge 1A “deletes failing tests” → Quick Lookup by Problem → [AP10 — Overpowered Coding Agent](../../skills/sl-sensemaker/catalog/anti-patterns/AP10-overpowered-coding-agent.md) and [D02: Test-Before-Done](../../skills/sl-sensemaker/catalog/families/D-verification-evaluation/patterns/D02-test-before-done.md). Family-first, Verification & Evaluation links to both and the regression-testing use case reaches the same files.
- **Result.** Scope writes to the implementation files when tests do not need edits. Run independently authored, protected checks. The baseline only detects the second bug if it exercises the affected behavior. A prompt restriction alone cannot protect the baseline.

### Long session loses decisions or requirements (P-S02, P-04, P-28)

- **Constraints and distinction.** The user can summarize or start a fresh CLI session and can maintain project files. Is the missing decision still visible in the conversation or in an authoritative record?
- **Route checked.** Bridge 1C “forgot decisions or requirements in a long session” → [Context Compaction](../../skills/sl-sensemaker/catalog/families/E-context-engineering/patterns/context-compaction.md) and [Repository-as-System-of-Record](../../skills/sl-sensemaker/catalog/families/E-context-engineering/patterns/repository-as-system-of-record.md). Family-first, Context Engineering and the debugging context use case link to both.
- **Result.** Compact available decisions, findings, current state, and next steps. Keep durable decisions in the authoritative project record when files are available. Neither entry recovers a decision absent from all available records.

### Agent reintroduces an explicitly rejected approach (P-S03)

- **Constraints and distinction.** The user can start a fresh chat but cannot change the harness. Is the agent repeatedly suggesting the same path in conversation, or editing intentionally unusual code? Is there an observable failure to diagnose?
- **Route checked.** Bridge 1A “approach we explicitly rejected” → [Fresh-Context Retry](../../skills/sl-sensemaker/catalog/families/I-reliability-recovery/patterns/fresh-context-retry.md) and, for an unexplained failure, [Root-Cause-Before-Retry](../../skills/sl-sensemaker/catalog/families/I-reliability-recovery/patterns/root-cause-before-retry.md). Family-first, Reliability & Recovery has direct links to both.
- **Result.** A clean restart with actionable lessons may help if accumulated attempts are influencing the next turn. A user with diagnostic evidence can investigate the failure before retrying. No entry guarantees that an abandoned approach stays rejected. Intentional code has a different bridge row with [F02 — Repository-Local System of Record](../../skills/sl-sensemaker/catalog/families/F-harness-environment/patterns/F02-repository-local-system-of-record.md) for project rationale and [H02 — Programmatic Gate](../../skills/sl-sensemaker/catalog/families/H-deterministic-control/patterns/H02-programmatic-gate.md) for mechanically checkable invariants, with a gap for a code-specific marker workflow.

### Generated diff exceeds review capacity (P-22, P-23, P-24)

- **Constraints and distinction.** The user can request independently verifiable milestones and control whether the agent proceeds. Is this a pending draft, an applied change, or a plan for future work?
- **Route checked.** Bridge 1B “the diff is enormous” → [B5: Milestone / Checkpoint Planning](../../skills/sl-sensemaker/catalog/families/B-task-decomposition/patterns/B5-milestone-checkpoint.md), [K01 — Human-in-the-Loop Checkpoint](../../skills/sl-sensemaker/catalog/families/K-human-control/patterns/K01-human-in-the-loop-checkpoint.md), and [K05 — Draft/Preview Before Apply](../../skills/sl-sensemaker/catalog/families/K-human-control/patterns/K05-draft-preview-before-apply.md). Family-first, Task Decomposition and Human Control link to the same entries.
- **Result.** Future work can produce one verifiable artifact per milestone and pause for human review at phase boundaries. A tool that can hold writes supports preview before applying them. The catalog leaves review or splitting of an already oversized, applied diff open.

### Team isolation with no applicable local guidance (P-46, P-47)

- **Constraints and distinction.** A CLI user is concerned about losing collaboration with teammates. The question is about shared understanding among people, independent of how agent actions are monitored.
- **Route checked.** Bridge 1B “working with AI isolates me from teammates” identifies the gap. Read [K06 — Human-on-the-Loop Monitoring](../../skills/sl-sensemaker/catalog/families/K-human-control/patterns/K06-human-on-the-loop-monitoring.md) in Human Control and [D10: Human Calibration](../../skills/sl-sensemaker/catalog/families/D-verification-evaluation/patterns/D10-human-calibration.md) in Verification & Evaluation to check adjacent topics.
- **Result.** K06 monitors agent actions and D10 calibrates automated judges against human judgments. The local entries do not supply an applicable next step for sustaining teammate collaboration.
